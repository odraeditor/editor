# Jan Publishing Reference

Jan publishing turns confirmed Racket project configuration and copied output
inputs into a complete, deterministic publication manifest. The
`jan_output` package plans discovery, reuse, output ownership, and workflow
transitions. Generic Resource, process, credential, and remote-provider owners
retain all filesystem, tool, authentication, network, and deployment effects.

## Project configuration

`admit-publishing-configuration` accepts one complete configuration generation
with an exact provider generation and a bounded nonempty project set. Each
project defines:

- a stable identity, generation, and optional component projects;
- one or more source roots with recursion, include, exclude, and suffix rules;
- one destination and a build or build-and-upload action;
- a backend plus bounded shared and backend-specific scalar options;
- static-copy, link, sitemap, index, cache, and timestamp policies;
- an exact remote provider for build-and-upload projects; and
- concurrency, failure, cleanup, and retention policy.

Admission copies text values and rejects stale generations, duplicate projects
or roots, missing components, component cycles, unsafe relative rules, invalid
remote authority, and limits above the stable ceilings. Project composition is
ordered deterministically by dependencies and then identity.

## Discovery

Discovery examines only copied candidates beneath admitted source roots. A
nonrecursive root admits direct children only. Include and exclude prefixes are
applied before suffix selection; static resources additionally require the
project's explicit copy policy. Absolute paths and parent traversal reject the
complete discovery request.

Selected sources are sorted by relative path. Duplicate Resource identities or
paths reject instead of choosing one candidate. Discovery does not enumerate a
directory or read a file; a Resource owner supplies the bounded candidates.

## Complete manifests

`prepare_publication_manifest` validates the complete output set before any
write. Every generated or copied entry records its source and expected output
versions, path, size, links, output kind, reuse decision, and source,
dependency, backend, filter, setting, and tool digests. Synthetic sitemap and
index entries carry explicit generation inputs as well.

Internal links must refer to selected sources. Rewrite policies require a
planned output target, while validation policies reject unresolved links.
Output collisions, duplicate cache entries, malformed retained output, and an
incomplete manifest reject the whole plan.

Prior project-owned outputs absent from the new manifest receive a delete
decision. Outputs owned by another project, or not marked as generated by the
project, are preserved. These decisions are computed before writes begin.

## Incremental reuse

An output is reusable only when the retained output is complete and all six
semantic inputs match exactly:

1. source digest;
2. dependency digest;
3. backend digest;
4. filter digest;
5. setting digest; and
6. relevant tool digest.

Timestamp policy may help a provider discover candidates, but a matching
timestamp alone never proves reuse. Disabling the cache forces regeneration
without changing the manifest's other inputs.

## Local and remote outcomes

Publication workflow state distinguishes preparation, local generation, remote
delivery, retry, reconciliation, failure, and closure. A complete local build
enters `local-complete`; it never enters `published` without an explicit,
complete remote success from a project that requires remote delivery.

Remote progress accounts for exact uploaded and failed entry counts. Partial
delivery retains its manifest and can either retry within the bounded attempt
limit or enter reconciliation. An exhausted or conflicting transition is
rejected. Closing a local-only project records completion without claiming a
deployment.

## Cleanup and retention

Temporary resources created for publication must be confirmed cleaned before
the operation is complete. Expired, unprotected retained outputs must be
removed; protected outputs must not be removed; current outputs remain. The
project's retention generation limit is configuration, while deletion remains
an effect performed by the owning Resource provider.

## Failure and no-effect guarantees

Malformed configuration, stale generations, missing components, cycles,
unsafe paths, invalid links, output collisions, semantic cache mismatches,
partial deployment, exhausted retries, and incomplete cleanup remain explicit
outcomes. Planning never writes local output, invokes a backend, reads a
credential, contacts a remote service, or converts local success into remote
success.

## Focused validation

Use:

```sh
make jan-output-focused-test
```

The target checks Racket configuration admission and deterministic reference
fixtures, followed by strict `src/jan_output` tests for discovery, composition,
complete manifests, exact reuse, links, stale outputs, local and remote state,
retry, reconciliation, cleanup, and retention. It does not build `src/odra`,
perform filesystem publication, upload content, or run a repository-wide gate.
